# 결정 로그

## 2026-10-07 로그인 없는 사용자 구분 방식
- **정한 것:** 브라우저 익명 ID(A)와 닉네임 + 비밀번호(B)를 함께 쓴다. B가 A보다 우선하며, 다른 브라우저에서 B로 접근하면 같은 사용자로 승인한다.
- **왜:** 로그인 없이도 찜과 리뷰를 사람별로 구분하고, 기기를 바꿔도 이어서 쓸 수 있게 하려고.
- **다른 선택지:** A만 사용(단순하지만 브라우저를 바꾸면 찜과 비공개 리뷰를 잃음), B만 사용(기기를 바꿔도 되지만 찜과 비공개 리뷰를 묶을 기준이 없음).

## 2026-10-07 영화 데이터 출처
- **정한 것:** TMDB(The Movie Database) API를 사용한다.
- **왜:** 한국어 영화 정보와 포스터를 무료로 제공하고, 검색, 인기 영화 목록, 상세 정보를 모두 지원해서.
- **다른 선택지:** 영화 정보를 직접 입력, 다른 외부 API(사용자가 별도로 제안하지 않음).

## 2026-10-07 기술 스택
- **정한 것:** Next.js (React, TypeScript) + Tailwind CSS + Supabase (PostgreSQL) + bcrypt + Vercel.
- **왜:** 화면과 서버를 한 프로젝트에서 만들 수 있고, 서버가 TMDB를 대신 호출해서 API 키가 노출되지 않는다. 리뷰 공유와 닉네임 + 비밀번호 방식에 서버가 필요한데 따로 서버를 만들지 않아도 된다. 모두 무료로 시작할 수 있다.
- **다른 선택지:** React(Vite) + 별도 Express 서버(서버를 따로 만들고 배포해야 함), Supabase만 사용하고 서버 없이 만들기(TMDB 키를 숨기기 어렵고 비밀번호 로직이 불편함).

## 2026-10-07 비밀번호 복구 방법
- **정한 것:** 두 가지를 함께 쓴다. (1) 질문과 답변 형식의 2차 인증, (2) 사용자 요청을 받은 관리자(admin)가 직접 확인한 뒤 변경된 비밀번호를 알려 주는 방식.
- **왜:** 이메일이나 로그인 없이도 비밀번호를 되찾을 수 있게 하고, 질문과 답변을 잊은 경우에도 복구할 길을 남기려고.
- **다른 선택지:** 이메일로 재설정 링크 보내기(이메일 수집이 필요해서 로그인 없는 구조와 맞지 않음), 복구 없음(비밀번호를 잊으면 기존 찜과 리뷰를 잃음).
